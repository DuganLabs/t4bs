## What the user hits

**Player, no auth needed:** anyone opening a shared link to a puzzle that has since been removed gets bounced to the lobby with a red bar reading `error: puzzle-not-found`. That is a machine string, it names a thing the player never chose, and it offers nothing to do next. Every shared link hits this once its puzzle is gone.

**Admin:** if the first user-list request fails — a dropped connection, a 5xx, a session that lapsed between the auth check and this fetch — `/admin` shows "loading…" and keeps showing it, forever, with no retry button and no empty state. Next to it, a raw code like `admin-only` or `http-500`.

## Why it happens

**Player half.** The chain is intact and each link is doing exactly what it was written to do; the last one is the bug. `/?play=999` or `/play?play=999` → `decidePlayBoot` returns `{ kind: "start", puzzleId: 999 }` (`src/bn/client/play-boot.js:56-62`) → `start(999)` (`src/bn/client/hydrate.js:402-415`) → `POST /api/session` → the engine returns `{ error: "puzzle-not-found" }` (`shared/engine.js:53-54`) → `functions/api/session.js:32-33` sends it as a 400 with body `{error:"puzzle-not-found"}` → `src/lib/api.js:12` turns that into `new Error(data?.error || …)` → `src/bn/client/hydrate.js:411` does `error.set(String(e?.message || e))` → and `src/views/lobby.js:93` renders it verbatim:

```js
bindText(errAlert.content, () => `error: ${error() || ""}`);
```

That template literal is the defect: it prefixes a machine string with the word "error" and presents the result as user copy.

**Admin half.** `loadElevated()` (`src/views/admin.js:29-31`) only ever sets the error signal:

```js
function loadElevated() {
  api.modUsers("").then(elevated.set).catch(e => err.set(String(e.message || e)));
}
```

so on failure `elevated` stays `null` — and the list effect keys its loading state off exactly that (`src/views/admin.js:80-84`):

```js
if (u === null) {
  lists.innerHTML = `<p data-bn-region="status" role="status" aria-live="polite">loading…</p>`;
  return;
}
```

There is no `err()` check in that effect, so the spinner never clears, and nothing offers a retry. `src/views/admin.js:65` (`bindText(errAlert.content, () => err() || "")`) then prints the raw code beside it.

Narrower trigger than it looks: `src/bn/client/hydrate.js:636-639` gates non-admins into `mountNotice` before `createAdmin` is ever constructed, so `admin-only` is not the common cause — a network failure, a 5xx, or a session lapsing mid-flight is.

`src/views/moderate.js:49-50` already has the correct shape for the second half: `if (err()) { queueRoot.replaceChildren(); return; }` — the error branch is checked *before* the null-means-loading branch.

## The fix

1. **Map known error codes to human sentences.** Add a small exported map + lookup in `src/lib/api.js` (it is where the `Error` is minted, at `src/lib/api.js:12`, so the mapping lives beside the thing it translates) — e.g. `errorMessage(code)` returning a sentence for `puzzle-not-found`, `daily-already-played`, `admin-only`, `start-timeout`, `resume-timeout` and the `http-NNN` shape, with a generic fallback ("Something went wrong. Try again."). Put the map in `api.js` rather than in each view so `lobby.js`, `admin.js` and `moderate.js` cannot drift apart.
2. **Use it in the lobby.** `src/views/lobby.js:93` becomes `bindText(errAlert.content, () => errorMessage(error()))` — drop the `error: ` prefix entirely. For `puzzle-not-found` the sentence should say the round is gone and point at what is on screen, e.g. "That round isn't available any more. Pick a category below." The player is already on the lobby when this renders (`src/bn/client/hydrate.js:413-414` deliberately routes them there so the message and the choices are visible together), so the copy can refer to the list beneath it.
3. **Clear the admin spinner on failure.** In the list effect at `src/views/admin.js:80-84`, add `if (err()) { lists.replaceChildren(); return; }` as the first statement — the same order `src/views/moderate.js:49-50` uses. Copy that shape rather than inventing a new one.
4. **Give admin a retry.** `loadElevated` (`src/views/admin.js:29-31`) should `err.set(null)` on entry and the error region should render a `bnButton("Try again", { variant: "secondary", onClick: loadElevated })`. A retry button, not an automatic retry loop: the failure modes here include a lapsed session, where silent retries would hammer the endpoint and still fail.
5. **Use the map in admin too** — `src/views/admin.js:65` becomes `bindText(errAlert.content, () => errorMessage(err()))`. Do the same at `src/views/moderate.js:40` while you are there, for the same reason.

## How we will know it worked

The mapping is pure and therefore properly testable — this is the part to put a real test on. Add `errorMessage` assertions to a test file: it lives in `src/lib/api.js`, and `src/lib/game.test.js` is the existing home for `src/lib/` unit tests, so either extend that or add `src/lib/api.test.js` and register it in `package.json`'s `"test"` list (an explicit `node --test <files…>` enumeration, not a glob). Assert that `errorMessage("puzzle-not-found")` returns a sentence containing no hyphenated code, that an unknown code returns the generic fallback, and that `errorMessage(null)` returns `""`. These fail before the change because the function does not exist.

A source-scan guard for the views, in `src/views/play.test.js`'s style (`src/views/play.test.js:15-33`): assert `src/views/lobby.js` no longer contains the literal `` `error: ${ `` template.

The admin stuck-spinner is DOM behaviour with no harness (no jsdom in `devDependencies`, `package.json:49-56`). Check by hand: `npm run build && npx wrangler pages dev dist --port 8788`, sign in as an admin, open DevTools → Network → set `/api/moderate/users*` to block, reload `/admin`. Before: permanent "loading…". After: the spinner clears, a human message appears, and "Try again" works once the block is removed. For the player half, visit `http://localhost:8788/?play=999999`.

## Notes

- Do not change `shared/engine.js:53-54` or `functions/api/session.js:32-33`. The wire format `{error:"puzzle-not-found"}` is correct and is what the API contract is built on — CLAUDE.md also warns off casual engine changes. The bug is that a wire code is rendered as prose.
- `src/views/moderate.js:49-50` is the reference implementation for step 3. If you find yourself writing a third variant of this loading/error ordering, extract it instead.
- Same class as T4-051 (internal state described to the user in internal terms) but different files and different mechanism — no shared fix. T4-031 is also adjacent: a client state that no view renders honestly.
- `src/bn/client/hydrate.js:594-608`'s `mountNotice` is the existing pattern for a full-view "here is what happened and here is the way out"; if the admin failure state grows past an alert plus a button, use that rather than building a third notice shape.
